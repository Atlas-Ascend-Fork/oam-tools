# 掉卡专项诊断参考

诊断主流程、RAS关联和条件处置统一见 [掉卡处理流](fault-flows/card-drop-flow.md)，
网络候选见 [网络处理流](fault-flows/network-flow.md)。本页保留字段及机制索引，
只分析已有快照、DFX、告警和验证，不执行现场查卡、复位、DMI压测或换件。

## 事件与字段

掉卡入口需核对预期设备、故障时实际可见性及卡/槽位/逻辑Device/芯片映射。
进程无法访问设备、查询权限/环境错误与设备从系统消失分别记录。卡仍可查询但
有致命告警时，按具体故障定义分析，不凭告警等级称物理掉卡。

| 字段或材料 | 解释与核对 |
| --- | --- |
| `npu-smi`存档 | 设备列表、时间、来源与预期集合，不能用任意事后快照替代故障时状态 |
| `EL0001` | 读取具体设备不存在/异常详情，不能单码确定掉卡原因 |
| dmesg PCIe link down | 关联BDF/槽位、时间及恢复；链路断开不直接证明芯片自身损坏 |
| `event_id` / ECC / RAS | 按型号/版本解码并关联本次设备和时间，保留纠正、重试、恢复与未恢复状态 |
| `0x800000` + `mte_biu_rdwr_resp` | 适用的Stars/910B定义包括非法GM地址或跨设备访问超时；ECC/网络结论另需对应证据 |
| `0x0` / `timeout or trap error` | 回查适用定义、任务进展与指令，不能直接套历史超时根因 |
| DMI `PASS` / `GENERAL_WARN` / `EMERGENCY_WARN` | 只按实际版本、设备、检测项及覆盖解释；单次PASS不排故障，等级不直接指定损坏部件 |
| msnpureport / 1520 / core / KDump | 核对采集方式、型号、复位及时间范围；材料不存在不等于该类故障不存在 |

CE/corrected、UCE/UE/uncorrected、retry成功/失败和恢复动作不能合并为“未恢复
数据损坏”。告警物理地址与panic虚拟栈地址属于不同空间，须有匹配映射与故障
访问才能定位到被破坏对象；时间相近不补足这一链路。

## 网络记录索引

只解释已有诊断报告和设备查询存档，先核对端点、chip/port、协议、方向、队列、
故障窗口及业务负载。某次测试未见异常仅限所测范围，不能排除未覆盖的瞬态或路径。

| 原始字段或线索 | 核对方式 |
| --- | --- |
| 端口闪断/Down、非法报文 | 对应本次端点、物理路径和故障时刻，继续区分触发与传播 |
| 超时代答配置/统计 | 按设备与版本核对命令输出的列定义、启用状态、计数单位及周期；不能跨版本固定取倒数第三列 |
| HCCS可用credit / RoCE PFC | 分别解释信用数与按端口/方向/优先级队列的反压时长，关联业务进展；不是通用缓解动作 |
| `chip-id` / `port-id` | 关联具体接口与端口映射，不能只凭逻辑编号定位物理故障 |
| `rp_id_using_cnt` / `lp_id_using_cnt` | 保留原始计数及适用定义，结合时间变化、分配/释放与进展；存在或非零不独自证明窝包 |
| `rp_id_using_summit` / `lp_id_using_summit` | 峰值类线索，不能当作当前未释放量或持续卡住 |
| alloc / release | 核对同一计数口径和时间窗；差值可能是有效在途工作，不独自证明无法推进 |
| `drp_cnt` / `cur_pkt` | 区分丢包计数与当前包量，核对增量、清零/回绕及业务关联；字段存在不证明丢包或窝包 |
| `pkt_lprp_port_en_drop_cnt` | 按实际端口、定义和故障窗解释计数变化，继续查具体触发原因 |

未提供计数定义、单位或版本时保留原值和解释限制，不据字段名猜测阈值或物理
量。代答、丢包或流控观测即便成立，也仍需追踪原因；不能从单个计数直接开出
换卡、调压、恢复环境或网络配置处方。

## 机制索引

D001-D007保留为检索编号，均是机制线索；本库没有其完整原始现场、修复和复跑
记录，不能当作本次已命中已验证案例。

| 编号 | 方向 | 区分所需证据 |
| --- | --- | --- |
| D001 | 固定设备反复不可见 | 设备映射、负载/作业分配、关联RAS/链路及受控对照；重复位置不单独证明器件损坏 |
| D002 | PCIe链路异常 | 对应BDF/槽位的链路记录与可见性变化，继续区分插槽、电源、复位、驱动及器件原因 |
| D003 | 灵衢超时代答候选 | 适用设备的代答记录、端点/路径与故障窗关联，继续追原因 |
| D004 | 端口闪断候选 | 具体端口与链路事件、时间、业务影响及恢复记录 |
| D005 | 丢包/窝包候选 | 匹配计数定义、时间增量、在途/释放和无法推进证据，不能只用字段存在 |
| D006 | RAS/ECC与AI Core异常关联 | 正确解码的事件、时间/设备/任务及可解释的因果；事件不自动意味着持续器件缺陷 |
| D007 | A3跨设备访问/代答候选 | 适用型号和网络记录，保留非法GM地址、生命周期及其他候选 |

## 已知低层签名的闭合规则

掉卡、Hard LOCKUP 或心跳丢失只是现象层。命中下列签名时，必须继续把组件、版本和首错绑定到同一设备/时间窗；未命中时不得套用对应根因：

| 低层签名 | 需要同时闭合的组件与证据 | 未闭合时的表述 |
| --- | --- | --- |
| `IMP/DISP` 访问 UB 寄存器、Corner 时序异常 | 芯片缺陷/UB 控制器、对应 DFX/RAS 原文、设备和版本 | `known_issue` hypothesis，不写成资源耗尽 |
| PCIe 链路 `L0 -> Recovery`、`ERR_MISC_00`、`SW ACSVIOL` | PCIe/RAS/软件 ACS 事件、BDF/端点和故障时间 | 保留 PCIe/RAS 候选，不归因 Runtime/TSFW 清理 |
| `multi_ecc_num > 8`、`memory_multi_ecc_record`、`misc1 requestor_id` | ECC 快恢分支、边界检查/请求者判定字段、同一 Oops/ESR 链 | 只能确认 ECC 传播，缺字段时不写具体越界修复 |
| 重复问题单或同类故障单 | 问题单 ID、芯片/版本适用性、现场低层签名逐项匹配 | 作为有条件案例，不用相似日期或卡号替代证据 |

`SMMU/CMDQ`、资源耗尽、驱动注册失败和芯片缺陷是不同候选，不能因都出现“心跳丢失”互相替代。卡仍在管理面可见时，分别记录 `card_present`、`device_os_panic`、`PCIe/RAS` 和 `known_issue` 四层状态；管理面可见不否定设备 OS panic 或未注册状态，但也不等于物理掉卡。

## 修复与验证

已有硬件定位及产品处置规则支持时，才提出对应隔离/维护或换件建议；需要即时
止损时说明依据和临时性质。检测命令、资源需求和恢复动作按适用版本核对，
不把旧模板参数、固定Host内存需求或恢复选项通用于所有现场。

机制成立与修复验证分别说明。只有实际换件/软件或网络修正后的原失败条件、
任务结果与相关回归均有记录时，才限定已解决范围；失败、未执行或范围不足
保留对应状态。没有验证不抹去已有故障事实，也不证明处方已通过。
