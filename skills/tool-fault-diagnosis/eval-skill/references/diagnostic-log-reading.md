# 大日志与重复运行

扫描器的场景分数不是诊断结论。`errors[0]` 取决于文件遍历顺序，并非全局首错。前缀扫描的 `coverage` 或读取工具的截断表示存在未读材料：对遗漏文件及尾部继续检索，围绕命中原文读取完整上下文和多行异常。检查是否存在多个故障，不用第一处关键词结束搜索。

文件规模已知后，先定位实际失败记录和所属运行窗口，避免让初始化注册或全量参数分布淹没故障。对错误解码做覆盖尾部的签名检索，保留完整的多值 `errcode` 和多句 `errorStr`；单码正则、前若干匹配或 ERROR 总数不能证明所有异常同因。对不同签名分别回读启动、异常及返回链，按任务身份区分重复打印与独立失败。

批量绑定参数、任务与结果前，先回读一个成功块和一个失败块，确认标记是开始、结束还是后置摘要。用匹配得到并核对类型的原始锚点关联，考虑 task 编号回卷及 PID/stream/flip/执行阶段；不按“最近前置标记”或手填行号默认配对。统计区分执行前拒绝、跳过、执行异常、成功和结果缺失，缺结果不等于执行失败。已有字段提取工具保留完整括号内 `errcode`，自写统计也不能漏掉逗号或后续错误解释。

下一次读取应有明确待区分的问题，并有望从现有材料得到答案。失败实体、直接机制和传播链已有原文支持，已见不同签名及相关竞争解释已核对、未读范围已说明时，应交付诊断与条件修复；无法从现有材料确认的上游细节作为缺口保留。重复计数、列完所有调用或再次确认同一窗口不作为交付门槛；只有需要全量范围结论时才补齐对应统计，不能将局部读取写成全量检查。
