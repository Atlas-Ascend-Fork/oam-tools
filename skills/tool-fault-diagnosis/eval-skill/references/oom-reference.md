# 内存 OOM 专项诊断参考

本页提供字段和机制索引；完整证据、容量计算及条件修复统一见
[OOM 处理流](fault-flows/oom-flow.md)。只分析已提供的日志、配置、内存曲线和
验证记录，不清理现场、不调整配额或重新运行任务。没有 core 不阻止首节点分析。

## 字段与材料

| 字段或来源 | 解释与核对 |
| --- | --- |
| `EL0004` / `HBM allocation failed` | 核对具体分配失败及侧别，不单码确认物理容量、碎片或泄漏 |
| `requested` / `available` | 核对同一请求、对象、分配器、时刻及单位；可用值不必等于物理HBM剩余量 |
| `memory not enough` / `Out of memory` | 回查最内层失败、有效框架配额和请求，不能只凭框架报错确认整卡已满 |
| `total` / `used` / `free` / reserved / allocated | 核对采样阶段、统计口径和相互包含关系；事后低占用或 reserved>allocated 不独自证明碎片 |
| 内核/cgroup OOM记录 | 关联被杀PID、容器限制、时间与实际失败；单独 `Kill process` 或137仍需上下文 |
| 退出码137 | 常见shell中的SIGKILL线索，也可能主动返回该数值；须核对退出记录，不能直接判OOM |
| `GEfinalize` / `GEFinalize` | GE清理线索，不单独证明进程提前退出或OOM |
| plog `debug` / `run` | 保留异常与正常分配/释放、进展和清理；不只筛ERROR，也不跨未校准主机机械排序 |
| 配置/版本变化 | 形成受控比较方向，变化与失败同现不独自证明因果 |

先对齐 host/PID/rank/Device、任务和阶段，建立局部顺序。跨源时钟无校准依据
时，使用通信/任务标识和依赖关联，保留不确定性；首报者不自动是故障源。
core、内核日志或采样缺失只限制相关判断，不把未提供变成已排除。

## 预算与生命周期

物理HBM、框架预算、当前活跃对象、缓存预留、其他进程/组件和执行资源配额
分别解释，不能把SQ/CQ资源失败直接改写为HBM容量不足。图/模型/stream编号不
代表存活数量，须用同一作用域的创建/销毁和实际统计。

容量计算使用相同对象和单位，区分 GB 与 GiB、包含关系和瞬时峰值。框架限额
限制允许分配量，过低会更早OOM；只有已证实框架预留挤占其他组件、且活跃工作集
仍可满足时，才考虑降低其预算。释放未占用缓存不能释放仍活跃Tensor。

长稳占用增长先区分预热、缓存、活跃对象及无法释放的分配。空闲高占用先核对
进程/对象归属；仅重启后恢复不能证明残留，更不能直接建议终止有效业务。

## 机制索引

以下O001-O007为机制参考，保留编号便于检索；没有对应完整原始现场、修复和
复跑记录，不作为已验证案例或本次同因证明。

| 编号 | 方向 | 区分所需证据 |
| --- | --- | --- |
| O001 | Device容量不足 | 同次分配失败、有效请求与可用容量，区分配额、请求异常和碎片 |
| O002 | Host OOM Kill | 匹配进程的内核/cgroup OOM记录及终止关系，不能只用137 |
| O003 | 版本变更相关内存行为 | 可比输入、并发、阶段、配置和变更前后记录，区分相关与因果 |
| O004 | 残留分配/进程 | 已失效对象或进程归属及未释放记录，区分可复用缓存和有效工作 |
| O005 | 框架预算/内存池约束 | 同次失败请求、实际生效配额、活跃量与其他组件预算 |
| O006 | 业务/参数改变内存需求 | shape/batch/并发或对象生命周期变化与峰值需求的对应关系 |
| O007 | OOM后的退出/通信等待 | 对应生产者异常、真实退出及等待操作的因果关联，不能拼接不同现场 |

## 修复与验证

按证据选择降低实际需求、修正异常尺寸、调整有效配额、释放可回收缓存或修复
生命周期等方向，标明适用条件与代价。Host cgroup、Device容量、框架配额和
驱动执行资源是不同约束，不能互换处方。

用原失败输入、相同阶段/并发及相关边界检查分配、输出正确性和内存回归。
已有验证明确通过才记录已解决范围；失败、未执行与覆盖不足分别说明。
