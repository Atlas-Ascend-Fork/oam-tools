# 基线数据与验收口径

## 来源状态

旧版数表没有提供芯片型号、原始测量记录、脚本或完整环境，不能验证“单卡CANN8.5.0、100次迭代、前10次预热”的声明，现移除这些未验证数值。它们不能作为实测基线、性能承诺或精度验收线。

## 基础算子与模型基线

MatMulV2、LayerNorm、FlashAttention、Conv2d及模型级训练/推理均使用对应任务的实际记录。每项基线至少包含：

| 内容 | 需记录的信息 |
|------|--------------|
| 来源 | 原始结果、测量脚本/命令、记录日期及可核对版本/hash |
| 环境 | NPU型号/数量/资源配置、Host、CANN/Driver/Firmware、框架及插件 |
| 负载 | 算子/模型版本、shape、dtype、布局、batch、序列长度及精度模式 |
| 测量口径 | 预热与采样分别多少次，统计量、同步点、是否包含编译/传输及并发负载 |
| 性能 | Device与端到端时间分别记录，吞吐量的分子/窗口，profiling来源 |
| 精度 | 参考实现、输入/种子、误差定义、非有限值检查及既定业务容限 |
| 可比性 | 与当前记录不同的条件及其影响；缺少同条件基线时不作达标结论 |

计算效率使用明确的运算量口径。例如稠密矩阵乘可采用约`2*M*N*K`次浮点运算，并记录采用该口径；TFLOPS需由该运算量除以实际秒数再除以`10^12`，使用计算工具保留操作数。不能混用单算子与端到端时间。

## 精度与性能验收

精度容限来自算子契约、模型任务要求或已约定测试规范，需明确绝对/相对误差、零值、NaN/Inf及不同输入范围的处理。dtype本身不能决定统一max_diff合格线，不能通过放宽阈值掩盖回归。

性能目标来自同条件历史基线或任务预算。AICore利用率、带宽利用率和固定TFLOPS不构成跨型号/shape的通用达标线；需结合关键路径、计数器定义与实际瓶颈解释。缺少基线时交付当前测量和限制，补充采样属于明确的后续验证计划。

## errMsg 质量达标标准

### 综合质量分等级

| 质量等级 | 综合质量分 | 含义 | 处理建议 |
|---------|---------|------|---------|
| **EXCELLENT** | ≥ 90 | errMsg 较完整，仍需核对因果证据 | 记录可复核的日志样本 |
| **GOOD** | 70 ~ 89 | errMsg 有可用定位信息，结合原始上下文分析 | P3 记录可改进项 |
| **FAIR** | 50 ~ 69 | errMsg 存在明显缺口，说明受限判断 | P2 给出日志改进建议 |
| **POOR** | < 50 | errMsg 信息较少，继续分析其他已有材料 | P1 记录缺口与改进建议，不自动重跑 |

### 各维度达标阈值

| 维度 | 指标 | 达标值 | EXCELLENT | GOOD | FAIR | POOR |
|------|------|--------|-----------|------|------|------|
| **识别完整性** | 首报错码已提取 | true | true | true | true | false |
| | 错误级联深度 | ≤ 3 | ≤ 2 | ≤ 3 | ≤ 5 | > 5 |
| **文档符合度** | 文档记录率 | ≥ 80% | ≥ 95% | ≥ 80% | ≥ 60% | < 60% |
| | 未记录错误码数量 | 0（或仅 E\*9\*\*\*） | 0 | ≤ 1 | ≤ 3 | > 3 |
| | 描述与文档一致 | true | true | true | N/A | false |
| **格式规范度** | 错误码格式合规率 | 100% | 100% | 100% | ≥ 90% | < 90% |
| | 含 Ascend Error Message 块 | true | true | true | N/A | false |
| | 日志行格式合规率 | ≥ 90% | ≥ 95% | ≥ 90% | ≥ 75% | < 75% |
| | 含文件名+行号信息率 | ≥ 80% | ≥ 90% | ≥ 80% | ≥ 60% | < 60% |
| **问题指导性** | 能确定问题模块 | true | true | true | true | false |
| | AI Core Error 含 fault_kernel_name | true | true | true | false | false |
| | 含定位三要素（device/stream/task） | true | true | true | false | false |
| | 含根因提示词 | true | true | true | — | false |
| | 有明确排查方向的错误码比例 | ≥ 80% | ≥ 90% | ≥ 80% | ≥ 60% | < 60% |
| | 指导性评分 | ≥ 70 | ≥ 85 | ≥ 70 | ≥ 50 | < 50 |

### 按场景的 minimum 要求

| 场景 | 必须满足的最低要求 |
|------|----------------|
| AI Core Error（EZ9999）| 首报错码已提取 + `Ascend Error Message` 块完整 + `fault_kernel_name` 存在 + `device_id/stream_id/task_id` 三要素 |
| OOM（EL0004 / HBM OOM）| 首报错码已提取 + 错误描述含内存相关关键词（memory/OOM/allocation）|
| HCCL 超时（EI0002）| 首报错码已提取 + 包含超时等待时长（wait_time 或 timeout 字段）|
| 进程中断 / coredump | 首报错码已提取 + 含 C++ Call Stack 或 Python Traceback |
| 进程卡住 | 无错误码时须有最后一条 INFO 日志的时间戳 + 卡住阶段描述 |

## 诊断可信度达标标准

> 由评估 Skill 的 `assess_confidence.py` 给出，评分规范见 eval-skill 的
> `references/confidence-assessment.md`。errMsg 质量衡量的是**日志本身**好不好用，
> 诊断可信度衡量的是**结论**站不站得住，两者独立。

分数、等级和检查项统一按 [可信度规范](../../eval-skill/references/confidence-assessment.md)，案例准入按 [案例沉淀规范](../../eval-skill/references/case-contribution.md)。本页不另设维度达标线、场景门槛或评分上限。总分不代替每项主张的因果证据；材料不全时仍保留已证实机制、有依据的候选根因和不能继续缩界的位置，不自动补采。

### 各场景可核对的证据

下列材料用于解释实际证据边界，缺失时记录其影响，不决定可达到的等级：

| 场景 | 证据核对内容 |
|------|-------------------|
| AI Core Error（EZ9999）| 嵌套错误原文、`fault_kernel_name`、device/stream/task、已有 msaicerr 结果及其匹配范围 |
| OOM（EL0004 / HBM OOM）| 内存占用来源已量化（参数/激活/通信 buffer）+ `npu-smi` 或 profiling 佐证 |
| HCCL 超时（EI0002）| 各 rank 状态、首错候选、网络/慢节点假设的支持证据和反证 |
| 进程中断 / coredump | core 与 exe 匹配关系、符号质量、可解析的崩溃帧及源码/版本对应关系 |
| 进程卡住 | 已有堆栈快照、卡住阶段及 fork 死锁/HCCL 超时等竞争解释 |
| 性能劣化 | profiling 数据 + 基线对比 + 瓶颈类型已定位（计算/带宽/调度）|
