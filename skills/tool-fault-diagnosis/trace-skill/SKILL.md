# CANN Fault Trace

Build one fault-centered trace from one collection or reproduction boundary. Keep separate packages separate: identities, deduplication, time alignment, and relationships are package-local.

## Run

Invoke the deterministic generator from this skill directory:

```bash
python3 scripts/build_fault_trace.py <log-directory-or-archive> --output-dir <artifact-directory>
```

The output directory receives:

- `fault-trace.json`: versioned evidence contract, including the selected anchor's `component_chain` summary when generated by the current version.
- `tracing-report.html`: canonical self-contained offline detailed report.
- `fault-trace.html`: byte-identical compatibility copy of `tracing-report.html` for existing callers.

Open either HTML file directly; it requires no network resources. Prefer `tracing-report.html` for new integrations.

Use caller evidence when available:

```bash
python3 scripts/build_fault_trace.py <input> --output-dir <output> \
  --anchor-id event-000123 \
  --cann-version 8.5.0 \
  --source-timezone +08:00
```

`--eval-anchor-json` accepts either:

```json
{"fault_anchor":{"event_id":"event-000123"}}
```

or a package-relative evidence locator:

```json
{"fault_anchor":{"source_path":"host/log/debug/plog/plog.log","line":321}}
```

An explicit `--anchor-id` takes precedence when both inputs are present. A requested ordinary event remains identified as caller-selected; it does not become an automatically detected severe event.

`--redaction-config` accepts only additive rules and cannot disable the built-in profile:

```json
{"additional_patterns":{"TOKEN":"secret-[A-Za-z0-9]+"}}
```

Pattern names are uppercase identifiers. Rules must not match empty text. The artifacts record rule names, not expressions.

Context defaults to 1,000,000 us before and 100,000 us after the anchor, with at most 20,000 non-chain events. Override these independently with `--context-before-us`, `--context-after-us`, and `--context-event-limit`. Proven-chain events are retained outside these limits.

## Interpret

- Treat only `proven` relationships as the highlighted call chain. Preserve `inferred`, `conflict`, and missing evidence as weaker or unresolved states.
- Read `component_chain` as a compact normal-call summary, not an error-propagation graph. Solid edges are proven calls; dashed inferred edges require both observed log participation and architecture support. Missing relations remain explicit gaps.
- A detailed-report deep link may include `view`, `anchor`, `component`, and `event`. Event selection takes precedence, then component, then anchor; invalid targets fall back visibly instead of producing an empty page.
- Treat wall-clock domains as incomparable until the artifact records alignment. `--source-timezone` permits absolute `epoch_us` conversion but does not prove Host/Device clock synchronization.
- Report a `partial` result directly, including missing logs, unaligned clocks, unmatched spans, scope ambiguity, parse gaps, orphan evidence, and context truncation.
- Trace reconstruction does not establish root cause. Hand root-cause diagnosis to `eval-skill`; hand formal metrics and diagnostic reporting to `metric-skill`.
- Describe controlled crash fixtures as parser/correlation validation only, not proof of complete production-fault reconstruction.

## Exit Status

- `0`: schema-valid complete or partial JSON plus canonical and compatibility HTML generated.
- `2`: invalid arguments, configuration, or unreadable input.
- `3`: no usable timestamped event or no usable/requested anchor.
- `4`: generation, Schema validation, rendering, or artifact-write failure.

When status is `3`, inspect `fault-trace-inventory.json` when present before requesting more logs. For contract fields and integration details, read [docs/specs/fault-trace-skill.md](docs/specs/fault-trace-skill.md).
