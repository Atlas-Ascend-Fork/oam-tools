# Fault Information Collection

## Description

It does not rerun services but only collects fault information, such as software and hardware information and logs.

## Command Format

```bash
asys collect --task_dir=path1 --tar="True" --output=path2
```

## Description

- **task\_dir**: optional parameter, used to specify the directory for collecting operator compilation files (including .o, .json, and other files) and dump files (including GE dump graphs, TF Adapter dump graphs, exception dump files, and others). If the task\_dir parameter is not specified, or if no files are collected from the directory specified by the task\_dir parameter, the asys tool automatically collects them from the environment.

    Automatic collection is affected by environment variables. Therefore, when running the asys command for collection, the environment variable values must be consistent with those used during service running; otherwise, the collected information may be inaccurate. The environment variables involved are as follows: ASCEND\_PROCESS\_LOG\_PATH, NPU\_COLLECT\_PATH, DUMP\_GRAPH\_PATH, ASCEND\_WORK\_PATH, ASCEND\_CACHE\_PATH, ASCEND\_CUSTOM\_OPP\_PATH. For detailed descriptions and constraints of each environment variable, see [*Environment Variable Reference*](https://hiascend.com/document/redirect/CannCommunityEnvRef).

- **tar:** optional parameter, specifies whether to compress the result output directory of the asys tool into a \*.tar.gz file. By default, the directory is not compressed. When the value is T or True, the directory is compressed into a \*.tar.gz file and the original directory is not retained. When the value is F or False, the directory is not compressed into a \*.tar.gz file. The parameter value is case-insensitive.
- **output**: optional parameter, whose value is used as the path prefix for the result output directory of the asys tool, that is, the final output directory is \{output\}/asys\_output\_timestamp. When the output parameter is not specified in the command line, the output result is stored in the directory where the command is executed. If the value specified for output is empty, an invalid string, or a path whose directory has no write permission, or if directory creation fails, the asys tool exits and reports an error.

## Usage Examples and Output Description

```bash
asys collect --task_dir=$HOME/cache_path --tar="True" --output=$HOME/dfx_info
```

After the command is executed, the fault information file directory under the \{output\}/asys\_output\_timestamp path is as follows:

```bash
├── asys_output_timestamp
   ├── software_info.txt            // Installation package version, environment variables, dependent software, and system information
   ├── hardware_info.txt            // Collects hardware information on the host and device sides. Host information includes kernel version, CPU model, memory and disk usage. Device information includes the number of devices and the number of AICore units.
   ├── status_info.txt              // Collects device information, including chip model, CPU and AI Core utilization.
   ├── health_result.txt            // Collects device health information, including fault codes and fault information.
   └── dfx
       ├── bbox                     // Black box information on the device side
       ├── data-dump                // Generates an L0 exception dump file when an AI Core error occurs on L0.
       ├── graph                    // Dump graph information, including dump graphs of GE and TF Adapter. L0 exception dump does not collect this information.
       ├── ops                      // Operator compilation information, including operator compilation *.o and *.json files and custom operator configuration information.
       ├── stackcore                // core file information when an error triggers coredump
       ├── atrace                   // trace dump information, including plaintext files parsed from trace binary files
       └── log
           ├── device
           │     ├──dev-os-{id}
           │           ├── firmware      // logs generated by the firmware
           │           ├── slogd         // maintenance and test logs of log-related processes
           │           ├── application   // non-EVENT application logs generated by service processes
           │           └── system        // logs generated by resident processes
           └── host
                ├── message         // message/syslog logs
                ├── install         // logs of historical package installation
                ├── cann            // application logs
                └── driver          // Host-side driver logs
```

**Among them, users can define the version information of third-party dependency software collected in the software\_info.txt file as needed**. In the “ascend\_system\_advisor/conf/dependent\_package.csv” file under the asys tool directory, add or delete configuration items. Each line corresponds to one configuration item, with the dependency name and query command separated by a comma, and no space after the comma. An example snippet is as follows:

```bash
make,make --version
cmake,cmake --version
unzip,unzip -v
zlib1g,dpkg -l zlib1g| grep zlib1g| grep ii
zlib1g-dev,dpkg -l zlib1g-dev| grep zlib1g-dev| grep ii
libsqlite3-dev,dpkg -l libsqlite3-dev| grep libsqlite3-dev| grep ii
openssl,dpkg -l openssl| grep openssl| grep ii
libssl-dev,dpkg -l libssl-dev| grep libssl-dev| grep ii
libffi-dev,dpkg -l libffi-dev| grep libffi-dev| grep ii
```
